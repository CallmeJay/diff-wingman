# v0.0.10 验收记录

基线：`main`，开发前 HEAD `34866a3`。开发开始时 `docs/roadmap.md` 已有 28 行未提交的 v0.0.10 至 v0.0.12 拟议计划；本轮保留并据此实施已确认的 v0.0.10。测试数据曾存放在独立的 `/private/tmp/diff-wingman-v10-qa`，验收后已清理；没有调用 Codex 生成导读。

## 已验证

- `pnpm check:v9`：2/2。现有功能归属测试仍证明同文件的不同 hunk 只映射到各自功能，且固定提交范围的 commit subject 只作归纳线索。
- `pnpm build`：TypeScript、Vite 和服务端编译通过。Vite 仍有既有的大 chunk 提示。`git diff --check` 通过。
- 本地浏览器使用真实临时 Git 提交生成快照，导读由测试脚本填入独立数据目录。在浏览器实际 CSS 视口约 1163px 时，建档侧栏展开后代码区约 494px，打开快照自动收起后约 709px；标题仍显示仓库、固定端点和“重新选择”。
- 点击“重新选择”恢复原仓库、版本输入和最近快照；修改基线后建立另一快照，快照 ID 变化且侧栏再次自动收起。刷新页面后恢复该快照并保持侧栏收起。
- AI 面板的功能清单位于逐块解释之前，显示 2 个功能主题、已归类 3/3、待人工核对 0。点击功能与文件可跳到跨文件 hunk；切换同一文件的另一功能后，当前功能标签和变更块位置同步更新。长路径文件的完整路径保留在按钮提示和当前文件信息中。
- 并排/内联入口直接显示在代码标题栏。长代码行在两种模式下保持在原有 Monaco 阅读区，长路径没有遮挡切换入口；实际 CSS 视口约 1309px、927px、663px、618px 均未出现页面横向溢出，窄窗口仍可找到内联入口。
- 另一个模拟旧导读没有提交描述，且 2 处变更中 1 处未归类。界面显示“阅读分组”、已归类 1/2、待人工核对 1；点击未归类项跳到对应文件与 hunk，未误设当前功能高亮。

## 边界与未验证项

- 浏览器验收使用模拟导读，验证的是已保存导读到界面的呈现、定位和高亮；本轮没有调用真实 Codex，也没有复验模型对复杂 diff 的归类质量。
- 已查看长行在并排和内联模式的显示，但没有单独滚动到长行末尾；本轮未修改 Monaco 的滚动配置。
- 新版只调整 React 展示状态和现有跳转调用，没有修改快照、导读、评论或审查状态的存储格式与 API。验收未在真实用户旧评论、验证记录或 GitLab MR 上逐项重放；这些持久化状态由原有路径处理。
- 依项目规则，提交前未执行完整 `pnpm test`；本轮未执行 Git push 或桌面安装包打包。
