# 第二版需求与行为边界

依据用户已接受的第二版方案开发；这些入口与状态是本次授权范围。

| 用户原话 / 已接受方案 | 目标对象                                   | 允许动作                                             | 必须保持                                                 |
| --------------------- | ------------------------------------------ | ---------------------------------------------------- | -------------------------------------------------------- |
| 提交前审查            | 暂存区、已跟踪工作区、明确选择的未跟踪文件 | 从 HEAD 冻结只读快照；源内容变化时提示过期           | 既有 commit 到 commit 的比较语义、被审查仓库只读         |
| 需求对照              | 用户输入的本次需求和不得改变项             | 将原文逐条与变更、源码引用对应，展示未对应改动       | 缺少需求时不编造动机，不把模型判断当产品契约             |
| 业务流程导读          | 已有导读分组、源码引用                     | 按入口、输入、调用、状态、结果排列有证据的步骤       | 候选引用不冒充运行时调用关系，不自动运行测试             |
| 人工审查状态          | 当前快照的导读分组                         | 用户标记未阅读、已理解、有疑问、已核实，记录核实依据 | 模型不能自动改变人工状态；导读或快照变化使既有确认待重核 |

实现复用现有 Git、Babel、Codex、React、Monaco、Zod 和本地存储；新数据需兼容第一版已保存快照。验证以真实临时 Git 仓库、原有测试及浏览器端可观察结果为准。
