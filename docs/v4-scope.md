# 第四版范围与契约

第四版只针对两个 commit 的固定快照，把第三版人工依据旁的“需要验证”变成可选择、可追溯的运行记录。

| 用户确认的目标 | 目标对象 | 允许动作 | 必须保持 |
| --- | --- | --- | --- |
| 从待确认判断生成验证清单 | 当前导读中的逐条判断和分组问题 | 列出待核对对象；由人工填写触发条件与预期可观察结果 | 不凭导读自动编造测试命令或宣称覆盖 |
| 对同一份 commit 源码执行检查 | 目标 commit 的 Git blob 和根目录 `package.json` 检查脚本 | 人工选定后还原到工具临时目录，在本机已有的 Docker 镜像中执行 | 不 checkout、不写 index、不写被审查仓库；Docker 不可用时不在宿主机回退执行 |
| 保存可复现证据 | 命令、脚本内容、镜像 ID、commit、日志和退出状态 | 按快照保存，并放入 Markdown 报告；导读改变时标记关联待重核 | 退出码不自动改变人工判断，也不证明脚本覆盖了关联业务判断 |

执行边界：默认镜像 `node:22-alpine`，只使用本机现有镜像，不自动拉取；可通过 `REVIEW_HELPER_VERIFY_IMAGE` 指定本机镜像。容器关闭网络，源码只读挂载，临时目录可写；脚本执行限制 120 秒、512 MB、1 CPU、64 个进程，最多保留 32 KiB 标准输出和 32 KiB 标准错误。源码还原超过 120 秒即停止继续读取，单次 Git 读取最长 30 秒；每次最多 2500 个普通文件、单文件 8 MB、总计 64 MB。符号链接及子模块被拒绝。只展示根目录 `package.json` 中 `test`、`check`、`lint`、`typecheck`、`verify` 及对应冒号前缀脚本。脚本由 `npm run` 执行，并关闭 npm 的隐式前后置脚本；不安装依赖。缺少依赖或脚本需要写源码目录时会如实失败。

这一版没有 PR 平台同步、暂存区或工作区执行、脚本自动生成、依赖安装和自动人工结论。Docker 镜像中的依赖是否匹配目标 commit，需要由使用者根据镜像 ID 和脚本结果核对。
