# 第五版范围与契约

第五版先接 GitLab MR。它只读取平台信息，将 MR 的固定 diff 版本与本地 Git 对象对应，并在本机整理人工评论草稿。GitHub PR 和向平台写入不属于本版。

| 用户确认的目标 | 目标对象 | 允许动作 | 必须保持 |
| --- | --- | --- | --- |
| 对应团队 MR | 指定本地仓库和 GitLab MR 链接 | 读取 MR 的 `base/head/start` SHA、diff 版本与文件列表，和本地固定快照逐项核对 | 不自动 fetch、checkout、修改被审查仓库；不把 MR 描述推断为需求 |
| 整理评论草稿 | 人工填写的问题、依据及 MR diff 新增/删除行 | 本地保存、编辑、删除、预览、复制和导出 | 不发布评论，不修改 MR 标题、描述、状态，不批准或合并 |
| 防止沿用旧结论 | GitLab diff 版本及固定快照 | 重新读取版本，变化时把草稿和人工结论标为待重核，并阻止新增、编辑和复制旧草稿 | 旧记录保留在旧快照，不自动迁移到新行 |

GitLab API 只发 GET 请求。私有项目可设置 `REVIEW_HELPER_GITLAB_TOKEN`，同时必须设置 `REVIEW_HELPER_GITLAB_HOST` 为 MR 的域名（如 `gitlab.example.com`），避免将令牌发送到其他仓库配置的远端。令牌不写入本地快照或报告。无令牌时仅能读取平台允许匿名访问的 MR。

导入时 MR 链接必须与所选仓库的 Git 远端项目和域名一致。目标提交缺失、MR 正在更新、平台文件列表与本地 diff 不一致、文件 diff 被 GitLab 折叠或截断时，导入失败且不保存不完整的审查记录。单份 MR 限 300 个文件、20000 个变更行；单个 API 响应限 12 MB。只有平台 diff 中实际新增或删除的行可作为草稿位置。导出可以保留过期草稿，但会明确标记待重核；复制单条草稿前会再次检查 MR 版本。

旧版两个 commit、暂存区、工作区、导读、人工状态与 Docker 验证路径继续保留。第五版没有自动分析 MR 描述、自动生成问题、平台写入或多平台同步。
