# v0.0.6 范围与契约

本版按 `docs/roadmap.md` 的 Review Core 范围开发。2026-09-23 已确认：评论覆盖所有快照；“待确认”同时包含 AI 未分析项和人工“有疑问”；默认上下文前后各 3 行、每次扩展 20 行，阅读位置按快照恢复，筛选偏好全局保存；快捷键采用 Alt+↑/↓、Alt+←/→、`/`、Alt+R、Alt+C。

| 用户要求 | 目标对象与允许动作 | 必须保持 |
| --- | --- | --- |
| 按变更块阅读 | 当前快照的文本 diff；折叠未改动代码、显示原始 hunk 范围、扩展上下文、逐块导航 | 真实变更始终可见；无法读取内容的文件仍显示原有原因 |
| 文件级状态和进度 | 人工设置未阅读、审查中、有疑问、已审查；统计与下一个未审查文件 | 打开或滚动不自动标记完成；状态绑定快照和文件内容；旧记录不跨内容变化继承 |
| 搜索和筛选 | 文件名/路径模糊搜索；变更类型、人工状态（含未审查汇总）、文件类型、有评论、待确认、无法分析 | 列表与树使用同一结果；筛选不修改审查记录；未审查包含未阅读和审查中 |
| 阅读导航与评论 | 文件/变更块前后导航、搜索、标记已审查、在当前位置建本地评论 | 输入框及编辑器输入时快捷键不触发；GitLab 原有草稿锚点、版本检查和导出规则不变；不发布评论 |
| 恢复 | 快照内保存文件、侧别、行和变更块；本机保存筛选偏好与最近快照 | 切换快照不沿用旧位置或人工状态；旧版记录缺少新字段时按未阅读处理 |

本地评论记录快照内的文件 ID、文件内容指纹、侧别、行号、正文和人工依据，每份快照最多 100 条。评论可在当前快照内编辑、删除；源码变化后旧快照仍可查看，不能自动迁移到新快照。GitLab MR 继续使用已有评论草稿数据和 API。

“待确认”的 AI 部分只使用导读中明确列出的 `unreviewed.changeId`；人工部分使用文件状态“有疑问”。“无法分析”指快照文件的 `issue` 已明确说明内容无法读取。未给出文件归属的整体导读限制不推测归入单个文件。

源码读取、Codex 导读、需求对照、笔记、现有评论草稿及 Markdown 报告行为保持原样。本版不增加托管平台、自动发布、自动修复或跨快照迁移人工结论。
