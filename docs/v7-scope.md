# v0.0.7 范围与契约

2026-09-23 确认 `1A2A3A4A`：人工选择同一 MR 已保存的旧快照；增加 hunk 级状态并只精确继承；评论仅在原 hunk 完全不变且唯一匹配时迁移；完整 MR 范围沿用 GitLab 的 merge base → source HEAD。

| 用户要求 | 允许变化 | 必须保持 |
| --- | --- | --- |
| 增量复审 | 导入最新 MR 时可选旧快照，展示新增、再次修改、不变、移除的文件和 hunk；来源证据不足时标待确认 | 固定快照不改变；无旧快照时继续完整审查；不自动读取旧版本源码或改动被审查仓库 |
| 安全继承 | 文件两侧内容及模式相同且唯一匹配时继承文件状态；hunk 的增删内容完全相同且唯一匹配时继承显式 hunk 状态；部分修改的文件整体待复审 | v0.0.6 仅有文件状态，不倒推为逐块人工结论；重复内容或不唯一匹配不自动继承；旧快照记录不变 |
| 评论闭环 | 本地评论和 MR 草稿支持单行、多行、文件级、类型、修改建议、解决状态、总览及定位；MR 更新后仅唯一不变的锚点迁移 | 旧版评论继续可读；无可靠位置时标待重新定位；最多 100 条；GitLab 仅 GET，不自动发布 |

文件以 Git 内容身份、hunk 以逐字相同的增删行匹配，不做相似文本迁移。路径变化、上下文位移和来源判定应展示原因。当前版本只由本地已保存快照比较，不依赖 GitLab 旧版本 diff 接口。最新 MR 导入仍须通过远端版本、本地 Git 对象和文件清单一致性检查。导入过程中出现冲突时不得覆盖旧人工记录。

评论类型与解决状态是本地审查信息，不代表 GitLab 讨论已解决。文件级评论没有行号；多行评论只允许在当前可评论的同一侧连续行。旧版未提供的新字段在展示时解释为单行、问题、未解决和当前锚点，不改写旧数据。

验收重点：只改一个 hunk 时未变文件不被重审；重复代码不迁移状态或评论；旧记录兼容；评论总览与 diff 标记使用同一快照数据；导入、编辑、导出不向 GitLab 写入。
