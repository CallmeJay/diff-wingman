# v0.0.8 范围与契约

开发基线：2026-09-23，`main` 的 `c0e23c6`。当前用户请求为“继续开发 v0.0.8 版本”；功能边界以 [路线图](roadmap.md)的 v0.0.8 段落为准。

| 路线图对象 | 允许变化 | 必须保持 |
| --- | --- | --- |
| Hunk 解释卡 | 在具体变更块旁展示行为前后、需求、失败路径、测试与缺口，并逐条标明证据来源 | 旧版分组导读继续可读；源码证据只指向本快照有效的文件、blob OID 和行范围；测试源码不充当执行结果 |
| 覆盖矩阵 | 按 hunk 汇总需求、导读、人工状态、评论和验证记录；未分析块单独列出 | v0.0.7 文件与 hunk 审查状态、评论、验证记录不被改写；过期记录不能显示为当前结论 |
| 符号上下文与影响链 | 在固定快照内按选中的完整 JS/TS/JSX/TSX 标识符，展示定义、直接关系、数据用途、前后变化、相关文件与定位 | 静态候选不能写成已证明的运行时调用；同名不同符号不得合并；不修改被审查仓库、Git index 或 GitLab |

2026-09-23 用户确认：生成导读前可选“整份生成”或“逐块按需”；按需模式仅在点击“生成此块解释”时调用 Codex，浏览变更块不会自动消耗额度。逐块理解状态单独保存，不改写 v0.0.7 审查进度，“已核实”需要人工依据；符号影响链首期支持两次提交及 GitLab MR，暂存区和工作区保留现有导读。

现有可复用能力：固定快照与源码引用、`validateGuide` 的变更覆盖校验、`planGuideBatches`、TypeScript 静态引用服务、逐块审查状态、评论和按快照保存的隔离验证记录。新关系必须保留文件来源与精确位置；索引范围不足时明确标为候选或待确认。

验收需覆盖正常、歧义和失败路径，包括重名局部变量、重命名导入、动态调用、目标文件未载入、版本变化、旧记录兼容以及从关系图跳转后返回。真实 Codex 生成、真实 GitLab MR 和桌面打包如未执行，应在验收记录中明确列出。
