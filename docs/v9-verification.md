# v0.0.9 验收记录

基线：`main`，开发前 HEAD `4e6e474`，工作区无已有改动。本记录对应 v0.0.9 实现，验证在提交前完成。

## 已验证

- `pnpm check:v9`：2/2。真实 Git 仓库中，同一文件的两个远隔 hunk 分别归属两个功能；两项清单都包含该文件，但各自只列自己的变更块。提交描述只读取祖先关系内的目标范围；反向比较和工作区模式不把无关提交当线索。
- `pnpm check:guide`：4/4。原有引用、完整覆盖、未分析文件和需求对照约束保持有效。
- `pnpm check:git`：3/3。固定提交端点、文件状态和特殊路径读取保持有效。
- `pnpm check:server`：1/1。HTTP 导读请求包含固定提交范围的 subject，完成后连同导读保存；取消或无效结果不覆盖旧导读。
- `pnpm check:v6`：2/2；`pnpm check:v8`：5/5。文件/逐块人工状态、阅读位置、评论和逐块解释的相关回归通过。两组监听型用例在默认沙箱因 `127.0.0.1` 监听权限报 `EPERM`，在允许本地监听的环境重跑通过。
- `pnpm build`：类型检查、Vite 生产构建和服务端编译通过。Vite 仍提示既有的大 chunk 警告。
- 本地浏览器：打开已有三文件审查快照，点击“提交失败时返回具体错误消息”，左侧出现 `src/panel.ts` 和 `src/panel.test.ts` 各自的 hunk。点击测试文件 hunk 后，当前文件和 hunk 标签切换到对应目标，Monaco 出现 7 行功能高亮。390px 视口下功能清单仍可滚动阅读，测试后已恢复默认视口。
- 真实 Codex 临时仓库试跑：一个固定提交范围含 2 处变更和 1 条 commit subject，模型归为 1 个功能、0 处未分析，`validateGuide` 对全部 2 个变更 ID 和源码引用校验通过。临时仓库已清理，未写入现有审查记录。
